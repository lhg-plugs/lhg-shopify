# lhg-sp-checkout：四步结账流程

> 目标：让用户"不假思索地把钱付了"。
> 核心纪律：**结账页每多一步操作，弃单率就涨一截**——四步是上限，不是下限；能三步就别四步。

## 1. 何时使用

- 搭建结账流程 → 按第 3 节逐项落实
- 结账页弃单率高 → 按第 6 节排查弃单点
- 测试结账 → 用第 5 节检查表逐项走查
- 用户问"要不要强制注册" → 答案在第 4 节第一条：不要

## 2. 输入与输出

- **输入**：site_spec.json 的 checkout 段（步骤定义、支付方式）
- **输出**：四步结账页 + 走查报告（checkout-tester 输出格式）
- **不输出**：产品页、信任页——那是其他 skill 的事

## 3. 四步结账规范

### 第 1 步：信息填写（越少越好）

- 必填只留三样：姓名、地址、电话（或邮箱）。其他全是选填
- 地址输入支持联想/自动填充，不许让用户逐字敲省市区
- 实时校验：电话格式错了当场提示，不许等到提交才报错

### 第 2 步：配送方式（给选择，不给惊吓）

- 至少 2 个选项：标准 / 加急，写清时效与价格
- 运费在这里**第一次**出现：如果产品页写了包邮，这里必须是 0
- 选完配送，总价实时更新

### 第 3 步：支付（安全感拉满）

- 支付方式 ≥2 种（卡 / PayPal / 本地支付三选二）
- 支付品牌标识（Visa/Mastercard/PayPal）必须可见——用户输卡号前要看到熟面孔
- 金额大字显示，旁边写"安全支付 · SSL 加密"

### 第 4 步：确认（买完不懵）

- 确认页三要素：订单号、金额、预计送达时间
- 告诉用户"确认邮件已发送到 xx 邮箱"
- 给一个明确的下一步："查看订单""继续逛逛"，不许是死路

### 全程常驻：订单摘要

四步每一屏都要能看到"买了啥、一共多少钱"。用户在任何一步产生"是不是被多收了"的怀疑，订单就没了。

## 4. 价格一致性铁律

产品页价格 = 购物车价格 = 结算页价格 = 支付页价格，四处必须一字不差。

- 优惠码：输错有提示，输对折扣**当场**算对，不许"支付时才发现没打折"
- 税费：跨境订单写清是否含税，不许到支付页突然多出一笔税
- 货币：全程一种货币，不许产品页美元、支付页人民币

价格对不上是 blocker，不是 warning——这是钱的问题。

## 5. 结账体验检查表（走查用）

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 游客结账 | 不登录能走完，全程无强制注册弹窗 |
| 2 | 步骤指示 | 每一步都知道"第几步、还剩几步" |
| 3 | 回退 | 每一步都能回上一步，购物车不丢 |
| 4 | 浏览器后退 | 按后退键不丢已填信息（至少不丢购物车） |
| 5 | 字段校验 | 填错当场提示，不等到提交 |
| 6 | 运费变化 | 换国家/地区，运费与总价实时更新 |
| 7 | 优惠码 | 错码有提示，对码折扣算对 |
| 8 | 支付调起 | 点支付能调起支付页（到这一步即停，不真付） |

测试用假数据，真卡不许进测试流程。

### 走查记录模板

```
用例：游客结账
步骤：产品页 → 加购 → 结账页 Step1 → Step2 → Step3 → 确认页
预期：全程无登录弹窗，四处价格一致（¥299）
实际：（填写）
结论：通过 / 失败（失败写复现步骤）
```

每个用例一张卡，失败项必须写清复现步骤，否则等于没测。

走查频率：结账流程每次改版必走查；日常每月抽查一次，防止"改 A 坏 B"。
走查人选：最好找没参与搭建的人走第一遍——自己测自己的流程，盲区最多。

### 移动端结账特别处理

移动端是结账主战场，桌面端流程直接搬过去会翻车：

- 一步一屏：移动端四步不要挤在一个长页面里，一步一屏，顶部步骤条常驻
- 键盘适配：电话框调起数字键盘，邮箱框调起带 @ 的键盘——输错率直接减半
- 按钮粘底：每屏的"下一步"按钮固定在屏幕底部，拇指区内
- 地址联想：移动端打字最痛苦，省市区必须支持联想选择，不许纯手输

## 6. 弃单点排查（按杀伤力排序）

1. **强制注册**：第一杀手。修法：游客结账，注册改成"支付成功后一键注册"
2. **运费刺客**：结账页运费和产品页说的不一样。修法：产品页写清，结账页一致
3. **价格跳变**：四处价格对不上。修法：第 4 节铁律
4. **步骤太长**：超过四步，或一步里有 10 个字段。修法：砍字段、砍步骤
5. **支付方式单一**：只有一种支付。修法：至少加一种本地主流支付
6. **没有安全感**：看不到支付标识、没有 SSL 提示。修法：第 3 步第 3 条

## 7. 反模式

1. **注册墙**："先注册才能买"——一半用户在这里流失
2. **幽灵运费**：全程不提运费，支付页突然 +50——用户感觉被骗
3. **优惠码黑洞**：输了码没反应，也不提示对错——用户反复试三次然后放弃
4. **死路确认页**：支付成功页只有一个"谢谢惠顾"，用户不知道去哪——至少给"查看订单"
5. **移动端缩水**：桌面端四步，移动端挤成一屏长表单——移动端是主战场，单独设计

## 8. 自检与反馈

### 质检门（结账流程交付前自查）

- [ ] 四步以内，游客结账可用
- [ ] 价格四处一致，优惠码逻辑走查通过
- [ ] `shopify_audit.py` 的 CHECK-* 规则全绿
- [ ] 第 5 节检查表 8 项全部通过

### 标准冒烟用例

1. 结账页强制登录 → 判定为 blocker，修法：改为游客结账
2. 产品页 ¥299、支付页 ¥349（含 50 运费但产品页写包邮）→ 价格一致性 blocker

发现 bug 或有改进建议，以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-shopify/issues，正文写清"复现步骤 → 实际表现 → 期望表现"。
